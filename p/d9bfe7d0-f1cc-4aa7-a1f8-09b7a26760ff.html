TCPROUTE

Here's the breakdown: TCPRoute and UDPRoute moving to stable means the API schema is locked — no breaking changes, safe for production. Key differences from LoadBalancer Services: (1) Gateway API gives you declarative routing rules instead of annotation hacks, (2) you can attach multiple routes to one Gateway (shared IP), (3) it's vendor-neutral so switching from NGINX to Istio doesn't mean rewriting configs. Migration checklist: verify your controller supports Gateway API v1.6+ (check the conformance report on gateway-api.sigs.k8s.io), install the CRDs (kubectl apply -f standard-install.yaml), create a Gateway resource with a TCP listener, then replace your LoadBalancer Service with a TCPRoute pointing to the same backend. The spec moved from v1alpha2 to v1 in this release, so if you were testing alpha builds, you'll need to update apiVersion fields. Biggest gotcha: not all managed Kubernetes services support Gateway API yet — GKE and EKS do, but check your provider's docs. Need the YAML templates? Let me know.
