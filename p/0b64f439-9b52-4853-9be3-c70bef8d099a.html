By the end, you'll have a real mental model for how inference cost tracking actually works. If you're running AI workloads on Kubernetes, or even just curious about cost observability, this is the video. Let's get into it. First, the problem. Traditional Kubernetes cost tools like Kubecost or even vanilla OpenCost track CPU and memory really well. But they treat GPUs as just another resource. That's fine for training workloads where a GPU runs at near 100% for hours. But inference is different. A model loads, runs for milliseconds, then idles. You're paying for the full GPU hour even if you only used 3 seconds of compute. Without inference-aware tracking, you have no idea which models are expensive, which endpoints are inefficient, or where to optimize. You're flying blind on the fastest-growing part of your cloud bill. OpenCost 1.121.0 fixes this. It tracks inference requests, token counts, model usage, and GPU time per request. Then it attributes actual dollar costs to each inference call. This is the first open-source tool that does this natively in Kubernetes. Not an external SaaS. Not a hacky script. Built into the CNCF sandbox project that 12,000+ companies already use. Before we install it, let's break down how it actually works. Because the architecture here is clever, and understanding it will make the config way easier. OpenCost already scrapes Prometheus metrics from your cluster. It knows CPU usage, memory, storage, network. For GPUs, it scrapes DCGM exporter metrics if you're on NVIDIA, or vendor equivalents. The new feature adds inference-aware metrics. It watches for specific labels and annotations on your inference Pods. Things like model name, endpoint, request count, token usage. Then it correlates those inference metrics with GPU utilization. So if a Pod running llama-3-8b used 200ms of GPU time for a request, OpenCost calculates the cost for that 200ms slice, not the full hour. It exposes this as a new API endpoint. You can query costs by model, by namespace, by endpoint, even by token tier if you're running multiple models. This is gold for chargeback and cost allocation. The key insight: OpenCost doesn't change how your inference workloads run. It just reads labels and metrics you should already be emitting. If you're not, we'll fix that in the walkthrough. Alright, let's install this. I'm assuming you have a running Kubernetes cluster with GPU nodes, Prometheus, and some inference workload. If you don't have Prometheus yet, pause here and install kube-prometheus-stack first. Step one: install OpenCost. We'll use Helm. Add the OpenCost repo, update it, then install the chart into the opencost namespace. Run helm repo add opencost, then helm repo update. Now install the chart. We'll create the namespace inline and pass a few custom values. That command disables the bundled Prometheus and points OpenCost to your existing one. Replace that URL with your actual Prometheus service endpoint. Check with kubectl get svc -n monitoring if you're not sure. Wait for the Pod to be ready. Run kubectl get pods -n opencost. You should see opencost running after 20-30 seconds. Step two: install DCGM exporter if you haven't already. This is the NVIDIA tool that exports GPU metrics to Prometheus. Without it, OpenCost can't see GPU usage. Add the NVIDIA Helm repo, update, then install dcgm-exporter into the gpu-operator namespace. Or wherever you run your GPU tooling. Verify it's scraping metrics. Check Prometheus targets at /targets. You should see dcgm-exporter endpoints in UP state. Step three: label your inference Pods. This is critical. OpenCost uses specific labels to identify which Pods are running inference workloads and which model they're serving. Add these labels to your Deployment or StatefulSet spec: opencost.io/inference equals true, and opencost.io/model equals your model name. Like llama-3-8b or whisper-large-v3. Here's an example Deployment snippet. Under metadata labels in the Pod template, add those two labels. Redeploy your workload after editing. If your inference service emits custom metrics, like request count or token usage, OpenCost will pick those up automatically. Just make sure they're scraped by Prometheus and labeled with the same Pod name. Step four: configure cloud pricing. OpenCost needs to know your GPU hourly cost. By default it uses AWS public pricing, but if you're on GCP, Azure, or have custom rates, set them in the Helm values. Create a values.yaml file. Under opencost, add a cloudProviderApiKey if you want real-time pricing, or manually set GPU hourly rates under customPricing. Upgrade your Helm release with those values. Run helm upgrade opencost opencost/opencost -n opencost -f values.yaml. This reconfigures OpenCost without downtime. Step five: query the inference cost API. OpenCost exposes a REST API on port 9003. We'll port-forward it locally and hit the new inference endpoint. Run kubectl port-forward to expose the service. Then in another terminal, curl the inference cost endpoint. You'll get a JSON response with cost breakdowns by model, namespace, and time window. Here's what mine looks like. Model llama-3-8b, 47 requests in the last hour, total cost 12 cents. You can filter by time range, namespace, or model with query params. Add ?window=7d for the last week, or &namespace=prod to scope it down. This is the data you'd feed into a dashboard, a Slack bot, or your internal cost allocation tool. OpenCost just becomes the source of truth for inference spend. Now let's talk about what this unlocks. First, per-model cost tracking. You can see which models are burning budget and which are efficient. Maybe your whisper model costs 10x more per request than you thought. Second, chargeback. If you're a platform team serving multiple product teams, you can now bill them accurately for inference usage. No more splitting GPU costs evenly or guessing. Third, optimization targeting. You can identify high-cost, low-value endpoints. Maybe a staging environment is running inference 24/7 with no traffic. Shut it down, save hundreds a month. Fourth, capacity planning. If you know your per-request cost and request volume trends, you can forecast GPU spend and right-size your node pools before the bill surprises you. This is especially huge for startups and small teams. You don't need a dedicated FinOps person or an expensive SaaS tool. OpenCost is free, open-source, and runs in your cluster. A few gotchas before we wrap. One: if your inference workload doesn't emit request metrics, OpenCost can't track per-request costs. It'll fall back to hourly GPU splits, which is still better than nothing. Two: token-level tracking requires your app to expose token counts as Prometheus metrics. Most inference servers like vLLM or TGI do this by default, but check your setup. Three: GPU pricing data might be stale if you're using public cloud APIs. OpenCost caches prices for 24 hours. If you negotiate custom rates, set them manually in customPricing. Four: this feature is brand new. Expect rough edges.
