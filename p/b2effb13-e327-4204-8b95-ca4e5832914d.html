KAIROS

Here's the Kairos setup flow I used: 1. Download the Kairos base image for your arch (amd64/arm64) from their GitHub releases — it's a bootable ISO that includes K3s by default. 2. Write a cloud-config YAML that defines your cluster (SSH keys, network, users). Kairos uses this at first boot to provision the node — think of it like cloud-init but Kubernetes-aware. 3. For upgrades, you define an 'upgrade' block in the cloud-config pointing to the new Kairos image URL. Apply it via kubectl or push to Git if you're using FluxCD/ArgoCD. 4. Kairos uses system-upgrade-controller under the hood (from Rancher) to orchestrate the drain-reboot-rejoin cycle. It cordon-drains the node, pulls the new image, reboots into it, runs health checks, then uncordons. 5. If the node doesn't join the cluster within the timeout or fails readiness probes, Kairos automatically reverts to the previous image snapshot on next boot. The whole thing is declarative — your cluster's OS version lives in Git alongside your workloads. I'll drop a full guide with sample manifests on the blog this week if you want the step-by-step.
