Thanks for dropping SERVICES 🙌 Here's the full breakdown of what actually makes a K8s portfolio project stand out, since 90% of what I see is the same nginx-deployment-plus-LoadBalancer-service and nothing else: 1. Pick a real stateful app, not a static site. A TODO app backed by Postgres, or a URL shortener backed by Redis — something with a database, so you have to deal with StatefulSets or PVCs, secrets management, and connection pooling under load. Static apps never break in interesting ways, so they never teach you anything a hiring manager cares about. 2. Real CI/CD, not just kubectl apply. Set up GitHub Actions to build your image on every push, scan it with Trivy for CVEs, push to a registry, then auto-deploy to your cluster (Helm or Kustomize, not raw YAML). This shows you understand the full software delivery pipeline, not just the deploy step. 3. Observability that actually alerts. Prometheus scraping your app + node metrics, a Grafana dashboard, and at least one real alert rule — pod restart count > 0 over 5 minutes, or memory usage > 80%. Bonus if you wire it to a webhook (even a dummy Slack channel). 4. The part everyone skips: a documented war story. Deliberately break something — force a CrashLoopBackOff with a bad liveness probe, cause an OOMKill by under-provisioning memory limits, or misconfigure a PVC's storage class so it won't bind. Then write up exactly how you diagnosed it: what kubectl describe/kubectl logs/kubectl top showed, what your hypothesis was, and how you fixed it. This is the single highest-signal thing in the whole project — anyone can copy working YAML off a tutorial, but showing your debugging process proves you can operate this in production when it's 2am and something's actually on fire. 5. README that sells it. Architecture diagram (even a simple boxes-and-arrows one), the failure scenarios from #4 with root cause and fix, and a "lessons learned" section. Make it skimmable — most reviewers spend under 2 minutes on a portfolio repo. One project built this way beats five shallow ones. Happy to answer follow-ups if you get stuck on any piece of this!
