Here's my full CrashLoopBackOff checklist: 1. kubectl describe pod <name> — look at Last State, Exit Code, and Events section 2. kubectl logs <name> --previous — see what the crashed container actually logged before dying 3. If exit code is 0 or 1: app-level issue (check logs). If 137: OOMKilled (check memory limits). If 143: SIGTERM (graceful shutdown, check probes). 4. kubectl get endpoints <service-name> — verify dependencies have ready pods backing them 5. Check your liveness/readiness probes — aggressive probes kill healthy pods during slow startup 6. For image issues: describe will show ImagePullBackOff or ErrImagePull in events The --previous flag is the secret weapon most beginners miss. Without it you're looking at logs from the current restart attempt, not the crash that caused the loop. Save this and walk through it next time a pod won't stabilize.
