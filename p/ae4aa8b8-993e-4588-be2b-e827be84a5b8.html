Here's what I learned about building a metrics exporter. First — Prometheus expects metrics at /metrics endpoint. Not /health, not /api/metrics. Just /metrics. Use the official Prometheus client library for your language. Don't write raw metric formats — you'll mess up the escaping. Expose it as a Service with a prometheus.io/scrape annotation. Without this, ServiceMonitor won't find it. Create a ServiceMonitor resource that tells Prometheus what to scrape. This is how Prometheus Operator discovers your metrics. Test locally first. Hit your /metrics endpoint with curl. If you see valid Prometheus format, you're 80% there. Most failures happen because labels don't match between Service and ServiceMonitor. EXPORTER

Here's a ServiceMonitor template that actually works: apiVersion: monitoring.coreos.com/v1 kind: ServiceMonitor metadata: name: my-app-metrics namespace: default spec: selector: matchLabels: app: my-app # MUST match your Service labels endpoints: - port: metrics # named port in your Service interval: 30s path: /metrics Key things: 1. matchLabels must exactly match your Service's labels 2. Port can be name ('metrics') or number (8080) 3. Deploy this in the same namespace as your Service 4. If using Prometheus Operator, also check the serviceMonitorSelector in your Prometheus resource Test with: kubectl get servicemonitor -n default Then check Prometheus UI → Status → Targets to confirm it's being scraped.
