Drop 'MODELPACK' below and I'll send you a starter template. — @k8s.simplified · Making Kubernetes click for DevOps beginners "I wasted 3 hours debugging a model that worked fine in Docker but broke in production. Here's what I learned about ModelPack. The problem? AI models need specific Python versions, CUDA drivers, and dependencies. Docker handles the runtime, but not the model format itself. ModelPack sits on top of Docker. It standardizes how you package the model weights, metadata, and inference code together. Think of it as a container for your container. Here's how it works. You define a modelpack.yaml with your model source, framework version, and entry point. Then build it. ModelPack outputs a Docker image with everything baked in. Same model, same behavior, whether you're running on your laptop or in Kubernetes. Why this matters: you can swap TensorFlow for PyTorch, upgrade CUDA, or move clouds without rewriting inference logic. The interface stays the same. Start small. Package one model with ModelPack this week. Your future self in production will thank you."

MODELPACK

Here's a minimal modelpack.yaml to get started: version: '1.0' model: name: my-sentiment-model framework: pytorch framework_version: '2.0.1' source: ./model_weights/ entrypoint: inference.py runtime: python_version: '3.10' cuda_version: '11.8' dependencies: - transformers==4.30.0 - torch==2.0.1 Run 'modelpack build --config modelpack.yaml' and it'll output a Docker image. You can then push that to your registry and deploy it to K8s like any other container. The key win: your inference.py stays the same even if you swap PyTorch for TensorFlow later — ModelPack handles the interface. Start with one model, see how it feels.
