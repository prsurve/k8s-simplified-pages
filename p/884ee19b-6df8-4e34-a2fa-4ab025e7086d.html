Your cluster has a bouncer and a guard dog. You just never met them. Meet Falkey (Falco) and Ky (Kyverno) — the two open source tools that actually keep your Kubernetes cluster safe. Kyverno is policy-as-code that blocks bad YAML at the gate before it's ever applied. Falco is runtime security that watches live and catches weird behavior after something's already running. Takeaway: prevention and detection are two different jobs. Run Kyverno to stop it before, run Falco to catch it after. Don't rely on just one. Here's the fast setup for both. For Kyverno (the gatekeeper): install with helm repo add kyverno https://kyverno.github.io/kyverno/ then helm install kyverno kyverno/kyverno -n kyverno --create-namespace. Once it's running, apply a ClusterPolicy — start with the 'disallow-privileged-containers' policy from Kyverno's official policy library (kyverno.io/policies) so any pod trying to run privileged gets denied at admission, before it ever schedules. For Falco (the lookout): install with helm repo add falcosecurity https://falcosecurity.github.io/charts then helm install falco falcosecurity/falco -n falco --create-namespace. Falco ships with default rules that flag things like a shell being spawned inside a container or a write to a sensitive system directory — tail the alerts with kubectl logs -n falco -l app.kubernetes.io/name=falco -f. Run both side by side on a kind or minikube test cluster first: try applying a privileged pod (Kyverno should deny it), then exec into a running pod and spawn a shell (Falco should alert on it) — seeing both fire is the fastest way to understand the difference between prevention and detection.
