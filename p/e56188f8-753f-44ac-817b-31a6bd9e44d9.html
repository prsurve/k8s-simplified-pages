CHECKLIST

Complete K8s 1.37 pre-upgrade runbook: **Before upgrade (test cluster):** 1. Check kubectl events output format: Run 'kubectl events --output wide' and verify any scripts parsing this output still work. Compare with 1.36 output. 2. Audit CronJob manifests: 'kubectl get cronjobs --all-namespaces -o yaml | grep apiVersion' — flag any still using batch/v1beta1. 3. Test PVC resize: If you use dynamic volume expansion, create test PVC, resize it, verify mount behavior matches 1.36. 4. API deprecation scan: 'kubectl get --raw /apis' and check for any v1beta1 APIs your workloads use. Focus on batch, storage, autoscaling. 5. Review release notes for your CNI plugin (Calico, Cilium, etc.) — some require updates before K8s 1.37. **Commands to run:** - 'kubectl api-resources | grep v1beta' (should return minimal results) - 'kubectl get events --all-namespaces --output json | jq .items[0]' (check JSON structure if you parse events) - 'kubectl get pods --all-namespaces -o yaml | grep -i sleep' (find if any existing lifecycle hooks conflict with new sleep action) **Migration steps:** 1. Upgrade test/dev cluster first, wait 48 hours, monitor for warnings in kube-apiserver logs. 2. Update CronJob manifests to batch/v1 (even though v1beta1 still works, start migration now). 3. If using VolumeAttributesClass (uncommon for beginners), test in staging with actual workload I/O patterns. 4. Update monitoring: Prometheus queries, Grafana dashboards, alert rules that depend on kubectl output. 5. Upgrade control plane first, then node pools in rolling fashion. **Rollback plan:** Control plane: snapshot etcd before upgrade. Nodes: keep 1.36 node pool running during canary, shift traffic back if issues. **Post-upgrade validation:** - All CronJobs triggered successfully - PVC resize operations complete without stuck volumes - No unexpected restarts in core workloads - Monitoring dashboards show accurate data For CKA exam: know the kubectl events syntax changes and Job success policy manifest structure.
